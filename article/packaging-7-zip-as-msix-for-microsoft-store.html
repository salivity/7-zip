Packaging 7-Zip as MSIX for Microsoft Store

Yes, 7-Zip can be packaged as an MSIX or AppX application for distribution through the Microsoft Store or enterprise deployment channels. Using Microsoft’s Desktop Bridge technology, the standard Win32 executable can be converted into a modern containerized package. However, achieving full context menu functionality and complying with Microsoft Store licensing and trademark policies require specific configuration steps.

Technical Feasibility and Conversion

7-Zip is a traditional Win32 application. It does not natively ship with an AppX or MSIX manifest, but it can be packaged using the MSIX Packaging Tool provided by Microsoft.

To convert 7-Zip into an MSIX package:

  1. Set up a clean environment, such as a dedicated virtual machine, with the MSIX Packaging Tool installed.
  2. Run the tool, select Application package, and provide the official 7-Zip installer (.msi or .exe).
  3. Follow the installation prompts to record file system and registry changes made by the installer.
  4. Define the primary executable (7zFM.exe) as the application entry point.
  5. Save the output as an .msix package signed with a valid code-signing certificate for testing.

Shell Integration Challenges

One of 7-Zip's primary features is its integration into the Windows File Explorer context menu via 7-zip.dll. Traditional MSIX containers use virtualization, which historically prevented Win32 shell extensions from loading directly into explorer.exe.

To preserve the context menu in a modern MSIX:

  • Windows 11: You must implement the IExplorerCommand interface and declare it in the AppxManifest.xml using the desktop4:FileExplorerClassicContextMenuHandler or modern context menu extensions.
  • Windows 10: Legacy shell extensions require a packaged COM server registration within the manifest, or the app must run with standard elevated desktop capabilities via the runFullTrust restricted capability.

Licensing and Microsoft Store Submission Rules

While repackaging 7-Zip is technically straightforward, distributing it publicly on the Microsoft Store introduces specific legal and policy requirements:

  • Open-Source Compliance: 7-Zip is licensed under the GNU LGPL (with some unRAR restrictions). Any repackaged version distributed to the public must comply with the LGPL license terms, which include providing access to the underlying source code and license text.
  • Intellectual Property and Impersonation: Microsoft Store policies strictly prohibit misleading users about an app's identity. Igor Pavlov owns the 7-Zip trademark and project. Submitting an unofficial repackaged version named "7-Zip" without explicit permission violates Store Policy 10.8 (Financial Transactions / Intellectual Property) and Policy 10.13.10 (Misleading App). Unofficial submissions must clearly identify themselves as third-party wrappers or forks to avoid rejection or removal.
