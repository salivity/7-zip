How 7-Zip Handles Nested Archives Without Extracting

7-Zip allows users to navigate and access files nested multiple layers deep within archives without requiring manual step-by-step extraction. This article explains the underlying mechanisms that make this possible, including 7-Zip's modular architecture, virtual folder mapping, temporary caching, and stream-based data processing.

Modular Archive Handlers

7-Zip relies on a modular architecture composed of independent codec and format handlers (such as 7z, ZIP, TAR, GZIP, and ISO). Each format handler implements standard COM-like interfaces (IInArchive, ISequentialInStream, and IInStream).

When a user opens an archive, 7-Zip inspects the file's binary header to identify the format and passes the byte stream to the matching handler. Because these handlers operate on abstract input streams rather than physical disk paths, a handler can read archive data sourced directly from another archive's decompressed output.

Virtual File System and GUI Tree Navigation

The 7-Zip File Manager treats archive containers as standard directory trees. When an archive is opened:

  1. Header Parsing: 7-Zip reads only the metadata and central directory of the archive to display its contents, avoiding full payload decompression.
  2. Sub-Archive Detection: When you double-click an inner archive (such as a .tar.gz or a .zip stored inside an .iso), the GUI recognizes the nested file as a supported archive type based on its extension and magic byte signatures.
  3. Stacked Navigation: The File Manager pushes the parent context onto an internal path stack, maintaining a chain of references to each ancestor archive.

Stream Processing and Temporary Storage

To read an archive nested inside another, 7-Zip uses two primary methods depending on the operation and archive format:

  • In-Memory Streaming: For sequential formats like .tar.gz, the outer decompression engine (GZIP) streams uncompressed bytes directly to the inner handler (TAR). The inner handler reads file metadata on the fly without writing the full uncompressed TAR container to disk.
  • Temporary Cache Extraction: Formats requiring random access (such as standard .zip or .7z archives that store their central directory at the end of the file) cannot always be processed purely as linear streams. In these cases, 7-Zip silently extracts the nested archive into the user's temporary directory (%TEMP%\7z*). The inner archive is then opened from this temporary location, abstracting the process from the user.

Updating Nested Archives

When a user modifies, adds, or deletes a file multiple layers deep, 7-Zip handles the update by reversing the process:

  1. The modified file is saved to the deepest active archive in the temporary cache.
  2. 7-Zip repacks the inner archive.
  3. The newly generated inner archive replaces the old version inside the parent archive.
  4. This update propagates upward through each layer until the root archive on disk is updated.
  5. The temporary files are flushed and deleted once the parent container is closed.
